# Product Status

This file keeps product state and roadmap notes out of the root README.

## Current Beta

- Private beta deployment targets Cloudflare Pages for the web app and Render for the API and LLM proxy.
- Closed beta access is controlled by `QUANTGYM_BETA_EMAIL_ALLOWLIST` on the API service.
- Email verification uses SMTP, currently documented for Resend.
- The frontend build writes deployment endpoints into `dist/config.js`.

## Completed Areas

- Cream / lavender / blue UI system with sidebar, top search, account chips, streak chip, score chip, Quant Wire, and generated mascot assets.
- Dashboard, prep plan, mock interview, interview experience notes, problem bank, skills radar, resume, jobs, community, network, mental math, news, and resources modules.
- Problem bank with 15 active sources and 2,997 compiled catalog problems.
- Personal favorites, problem social likes/comments, hot ranking, last score tracking, and mock-interview reuse.
- Email registration/login/password reset, Google JWT/JWKS login verification, cloud sync, localStorage fallback, and SQLite-backed state.
- LLM proxy for mock interviews, short feedback, study-log classification, resume advice, and RSS-based news.
- LeetCode Hot 100 tracking panel and packageable Chrome collector extension.

## Known Limits

- The frontend is still a static Vite app. Static route integrity, route-interaction contracts, formal module ownership with every browser-smoke interaction mapped to an owner, a real Chrome browser route smoke, UI contracts, and browser-evidence manifests are covered by local gates; beta usage should keep adding browser-executed journeys around newly identified high-risk paths.
- SQLite is fine for private beta and small groups. A read-only preflight/export script, `api-server/postgres/schema.sql`, `npm run check:postgres-cutover`, `npm run check:postgres-cutover:export-smoke`, `npm run build:postgres-cutover-packet`, and `npm run check:postgres-cutover:complete` now cover backup, redacted/full export safety, rejection of row-limited/truncated migration exports, schema/data shape checks, an offline include-sensitive export import plan, migration-window handoff files, and final cutover evidence positive/negative signoff shape including localhost, loopback, private-network, malformed target-host/database, and credential/query evidence-URL rejection, but a public multi-user release should still complete a real Postgres migration and deployment.
- Basic admin metrics/audit endpoints, an account-page ops overview, 24h HTTP error observability, optional HTTP error webhook alerts, API auth rate-limit enforcement, trusted-proxy CIDR controls for forwarded client IP headers, `npm run check:ops-alerts:runtime-smoke`, `npm run check:ops-alerts:production-fixture`, `npm run build:ops-alert-edge-packet`, and `npm run check:ops-alerts:production` readiness validation are available. The runtime smoke now verifies 404, auth 401, auth 429, spoofed `X-Forwarded-For` Google-login rate-limit behavior, alert delivery, and external alert payload sanitization; the production fixture verifies the production signoff gate rejects placeholder/short webhook tokens, placeholder/local/private-network/incomplete alert endpoints, wildcard proxy trust, and edge-rate-limit settings without leaking raw tokens or full dashboard URLs. The ops packet generates the Render env template, webhook contract, Cloudflare `/api/auth/*` edge-rule runbook, smoke payload, and signoff checklist. Production still needs a real alert receiver and edge-level rate limits configured with provider, notes, and HTTPS evidence URL signoff.
- The beta web app is live on `beta.quantgym.app`, but `quantgym.app` and `www.quantgym.app` currently return Cloudflare 525 SSL handshake errors. Keep the apex/WWW Cloudflare or origin SSL routing/redirect setup as a separate domain follow-up.
- Community image/video posts, account avatars, Memory resource images, and interview answer attachments now prefer the authenticated `/api/media` upload path and store returned media URLs in state JSON. Media storage supports local disk and S3/R2-compatible buckets; `npm run check:media-storage:runtime-smoke` covers local authenticated upload/download, persistence, audit logging, failure codes, MIME-derived object extensions when filenames disagree with payload type, direct-client spoofed forwarded host/proto headers being ignored for returned media URLs, and the S3/R2-compatible signed PUT/read-through/public-URL behavior against a temporary fake object store. `npm run check:media-storage:production-fixture` verifies the production gate rejects local/private-network object storage and public media URL shapes, embedded endpoint credentials, query-bearing public base URLs, placeholder/short object-storage credentials, unsafe bucket names/prefixes, and live-smoke cleanup failures against isolated fixtures; `npm run build:media-storage-packet` generates the Render env template, R2/S3 bucket/CDN runbook, object-storage contract, and live-smoke checklist; `npm run check:media-storage:production` validates production env shape; and `npm run check:media-storage:production -- --live` can sign off a real bucket/CDN by writing, reading, publicly fetching, and deleting a tiny readiness object. Production still needs a real bucket/CDN configured. LLM interview requests may still carry transient attachment contents for evaluation.
- The jobs module has a read-only `/api/jobs` catalog endpoint, static fallback data, optional crawler/vendor JSON feed ingestion, `npm run check:jobs-source:runtime-smoke` coverage for local feed ingest/cache/fallback behavior including unsafe source URL sanitization, unknown source type defaulting, invalid/future `postedAt` sanitization, HTTP errors, invalid JSON, and oversized payloads, `npm run check:jobs-source:production-fixture` coverage for production-shape, private-network/credential-bearing/query-bearing source URL rejection, placeholder/short source-token rejection, and live-feed data-quality guardrails, `npm run build:jobs-feed:public-ats` plus `npm run build:jobs-feed:publication-packet` for a checked-in Greenhouse source list, generated public-ATS snapshot, SHA-256 evidence, source list, stable HTTPS hosting runbook, production env template, and live-signoff checklist, front-end safe timestamp sorting for `crawler-ready` fallback jobs covered by route contracts plus browser smoke, and `npm run check:jobs-source:production -- --live` readiness validation for a real feed with internship and fulltime roles. Production still needs the generated or vendor feed hosted at a stable HTTPS URL and configured on the API.
- The Chrome extension has Manifest V3 validation, popup runtime smoke coverage, remote Board URL HTTPS enforcement with loopback HTTP allowed for local development, store-readiness validation, store listing assets, a public privacy page, a packaging script with zip/per-file SHA-256 integrity evidence, `npm run check:chrome-store-publication` for upload handoff, `npm run check:chrome-store-publication:fixture` for the published-signoff evidence contract including placeholder-looking item-id rejection, Chrome Web Store detail URL enforcement, private-network evidence URL rejection, and credential/query URL rejection, and `npm run build:chrome-store-publication-packet` for the developer-dashboard submission packet, listing snapshot, package SHA-256 evidence, published signoff env template, and final checklist. Chrome Web Store submission and review are still separate developer-account steps until `npm run check:chrome-store-publication:published` passes with the real published item evidence.
- Question-bank source rights now have a machine-readable `source-rights-manifest.json`, `npm run check:question-bank-rights` for the current private beta, `npm run check:question-bank-rights:public-smoke` for the public/commercial approval schema, and `npm run check:question-bank-rights:release-blockers` to prove the current public/commercial gates remain blocked for all active needs-review sources. Public/commercial distribution still requires per-source approval with recent review dates, non-placeholder externally reachable HTTPS evidence URLs without embedded credentials/query/fragment parts, approval types, evidence summaries, and redistribution scopes, and `npm run check:question-bank-rights:public` plus `npm run check:question-bank-rights:commercial` must pass before release.
